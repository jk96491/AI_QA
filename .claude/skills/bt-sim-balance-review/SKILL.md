# 밸런스 결론 전 점검 체크리스트

원문 제안서의 핵심 주장은 "측정을 공정하게"다. 아래 항목 중 하나라도 실패하면 결론 대신 **무엇을 더 돌려야 하는지**를 보고한다.

## 1. 측정 공정성

- [ ] 비교 대상들이 **같은 예산·같은 k·같은 최적화기**로 학습됐는가 (`summary.json` 의 meta 확인). 다르면 '최적화 편차'가 섞임.
- [ ] 모든 비교가 **평가 시드(EVAL_SEEDS)** 결과인가. 학습 중 `세대최고` 값으로 비교하지 않는다.
- [ ] 수렴했는가. "예산 소진"이고 곡선이 오르는 중이면 결론 보류, 예산을 늘려 재실행.
- [ ] 손 튜닝(default) 결과와 최적화 결과를 섞어 비교하지 않았는가 (E1 이 보여주듯 튜닝 편차가 직업 차이를 가린다).
- [ ] 같은 시나리오(패치)인가.
- [ ] **같은 게임 빌드**인가 (리포트 meta `game`, params.json 의 `game.version`). 빌드가 다르면 비교하지 않는다.

## 2. 통계

- [ ] 95% CI 가 겹치지 않는가. 겹치면 "차이 없음/판단 불가".
- [ ] 판수가 충분한가: `Stats.required_n(cv, delta)` 로 계산. `time_cv` 는 summary.json 에 있음.
  예) CV 0.03, 검출 목표 3% → 조건당 약 16판 / CV 0.10 → 175판.
- [ ] 효과 크기(Cohen d)와 % 차이를 함께 보고. p-값만으로 말하지 않는다 (정규 근사임).
- [ ] 여러 쌍을 비교했다면 다중 비교를 고려 (쌍 수가 많으면 보수적으로 해석).

## 3. 중도절단·실패

- [ ] 클리어율이 1.0 이 아니면 `clear_time`(클리어한 판만)과 `effective_time`(실패 포함)을 구분해 보고.
- [ ] **멈춘 판 비율(`stalled`)**: 실패로 벌점에 포함된다 (v1.2). 0 이 아니면 BT 가 빠져나오지 못하는 상황이 있다는 뜻 — 클리어율과 함께 보고하고, 반복되면 게임 BT 검토 요청.
- [ ] 무효 판(`invalid`) 은 환경 오류만 — 0 이 아니면 원인(`invalid_reasons`, 학습 로그 `무효 사유`)부터 보고. 무효 판은 집계에서 빠진다.

## 4. 해석

- [ ] 차이를 **행동 분포**(블록 점유율, 구간별 시간)로 설명할 수 있는가. 설명이 안 되면 시뮬레이터 버그를 의심.
- [ ] 학습된 파라미터가 range 끝에 붙어 있지 않은가. 붙어 있으면 "기획 의도 범위가 결과를 제한"했다고 명시.
- [ ] 패치 효과(E2/E3)와 비교해 차이가 밸런스 패치 한 번 크기(예: 보스 체력 5%)보다 큰가 작은가를 함께 말한다.
- [ ] BT **구조** 차이(직업별 블록 완성도)는 최적화로 제거되지 않는다는 한계를 언급.
- [ ] "장난감 환경 수치, 경향 비교용" 문구 포함.
