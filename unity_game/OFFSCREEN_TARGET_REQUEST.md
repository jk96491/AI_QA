# 요청: 시야 밖 퀘스트 대상의 위치를 플레이어가 알 수 있게 (학습 쪽 → Unity 세션, 2026-11-24)

> 플레이 프로토콜 변경 없음 (hello "0.3" 유지). 기존 `QaTag.alwaysKnown` / world.json `always_known` 을 쓴다. 밸런스 영향 없음.
> 사용자 결정 2026-11-24: "게임 쪽 해결이 맞다".

## 왜

학습 쪽이 작은 로컬 LLM(CPU)을 증류해서 플레이시키려 한다. 그 모델은 **대화 기록 없이 지금 관찰 + 직전 행동 결과만** 보고 행동을 고른다 (사용자 결정: 게임 진행은 지금 퀘스트 정보만 중요).

0.8.3 플레이에서 막히는 곳: 촌장 옆에서 퀘스트 4 "상인에게서 물약 사기" 를 받으면
- 퀘스트 `hint_targets = ["npc_merchant"]` 인데 상인이 시야 밖이라 `entities` 에 없다
- `move_to(npc_merchant)` → `failed / not_visible`
- 교사(Claude)는 **처음 화면에서 봤던 상인 위치를 기억**해서 근처 좌표로 갔다. 기억이 없는 모델은 갈 곳을 모른다

사람 플레이어도 겪을 문제다 (처음 본 위치를 잊으면 마을을 헤맨다). 보통 게임은 미니맵·퀘스트 마커로 푼다.

## 할 일 (권장안 A, 둘 다 해도 됨)

**A. 진행 중 퀘스트 목표의 대상은 위치를 안다 (퀘스트 마커)**
- 진행 중(`active`·`ready`) 퀘스트의 **완료되지 않은 목표**의 `hint_targets` 엔티티는, 같은 지역(zone)에 있으면 시야 밖이어도 `entities` 에 넣는다 (지금 `alwaysKnown` 과 같은 처리).
- 구분 필드 하나: 시야 안이면 지금처럼, 시야 밖이라 마커로만 아는 것은 `"known": "marker"` (선택, 이름은 Unity 판단). 다른 지역에 있는 대상은 넣지 않는다 (지역 입구로 가야 한다는 것은 `pilot_guide.rules` 3번이 이미 안내).
- `move_to(target)` 가 이 엔티티에 대해 `not_visible` 이 아니라 **길찾기로 걸어가도록** (시야 밖이어도 마커로 아는 대상).

**B. 마을 지도 (선택)**: 상인·촌장·경비병처럼 마을의 고정 NPC 를 `always_known` 으로 (미니맵에 표시되는 NPC). A 만으로 튜토리얼은 풀린다.

## 하지 않을 것

- 숨은 정보 공개 아님: 퀘스트 마커가 가리키는 대상만 (플레이어가 화면 마커로 아는 것). `-qaPlayOmniscient` 와 별개.
- 상점 구매 버튼 함정(`WorldState.cs:395`)은 그대로.
- 밸런스·전투 변경 없음.

## 검증

- 촌장 옆(퀘스트 4 직후)에서 관찰 `entities` 에 `npc_merchant` 가 있고 (`known: marker` 등), `move_to(npc_merchant)` 가 `done`.
- 퀘스트 5 의 `npc_guard` 도 같은 방식 (마을 남동쪽 초소, 늑대왕 처치 뒤).
- 학습 쪽 확인: `python -m play_agent relay --game 127.0.0.1:781x --record x.jsonl` 로 튜토리얼을 진행했을 때 좌표 이동 없이 id 이동만으로 끝까지 가고, 기록의 `grounding` 표시 0건.
- check-play / play_check 그대로 PASS (T3 지각 필터 항목에서 마커 대상이 예외로 보이면 그 항목 기대값을 같이 고친다 — 보고에 적기).
