- 작성: 학습 쪽, 2026-11-23 (사용자 요청: "플레이어 스킬 사용이 단조롭다 — 스킬 3개 이상, 스킬별 쿨타임이 보여야 하고 게임에 스킬 버튼이 표기돼야 한다", "BT 도 구조가 좀 더 복잡해야 하지 않을까")
- **진행 순서**: 지금 하고 있는 `BOSS_PATTERN_REQUEST.md`(아레나·`danger`·낙석/장판/탄막/돌진)를 **먼저 끝낸다**. 이 요청은 그 위에 올린다 —
  `Arena.cs` 좌표, `Obs.Danger`, 생존 필요도의 `danger` 항을 그대로 재사용한다. 아직 0.8.0 을 내지 않았다면 **같은 0.8.0** 에 넣고(학습 쪽 재학습을 한 번만), 이미 냈다면 0.8.1.
- 학습 쪽 설계 배경: `../docs/BANDIT_IMPALA_DESIGN.md` (IMPALA = 판 시작 한 번 결정하는 컨텍스트 밴딧. 시작 상황에 따라 최적 가중치가 달라지는 전투가 필요).

## 0. 지금 상태 (학습 쪽 측정, 참조 구현 game_sim · default 보스 · 직업별 30판)

| 직업 | 평타 비중 | 나머지 | 블록 비중 |
|---|---|---|---|
| 전사 | **80%** | 강타 14%, 칼날폭풍 4%, 방패 막기 3%, **돌진 0%** | dps 93% / burst 4% / survival 3% |
| 마법사 | 64% | 화염구 21%, 순간이동 6%, 보호막 5%, 메테오 4% | survival 59% / dps 38% / burst 4% |
| 궁수 | 64% | 조준 사격 29%, 속사 4%, 회피 3% | dps 80% / survival 16% / burst 4% |

- 스킬은 이미 4~5개·쿨타임도 있다. 단조로운 이유는 **역할(`SkillRole`)마다 스킬이 1개**라 블록 안에서 고를 게 없고(`UseBest(role)`), 결국 우선순위 고정 순환 + 평타.
- 전사 `charge`(gap_close) 는 한 번도 안 쓰인다 — `FarForCharge` 조건이 실제 전투에서 성립하지 않는 것으로 보임 (원인 확인 요청).
- 화면: 전투 뷰어(`BattleViewerHud`)는 비평타 스킬 이름을 로그 한 줄로만 찍는다. **스킬 버튼·쿨타임 표시 없음**. 플레이 모드 화면(`PlayView`)에도 없음.

## 1. 지켜야 할 것

- 결정성·고정 dt·판당 ≤ 100 ms·프로토콜 v1.3 그대로 (보스 패턴 요청 0장과 같음).
- **학습 대상 = 블록 가중치뿐** (SDK 규칙). 스킬 선택·콤보 순서는 블록 안의 **고정 규칙**이고 학습하지 않는다. 새 BT 상수는 가중치가 아닌 값(`group: bt`, 손 튜닝 default = 최종값).
- 블록 가중치 이름은 **모든 직업에 같은 이름·의미** (CLAUDE.md 6). 블록을 늘리면 describe `classes[].blocks` 에 선언 — 학습 쪽 코드는 블록 수에 무관하게 동작한다 (`learnable_space`). 기존 `policy.json`(출력 3개)은 새 빌드와 맞지 않으니 학습 쪽이 다시 학습한다.
- 페르소나는 가중치를 정하지 않는다 (θ·φ 등 `group: persona` 만).
- 직업 데이터를 바꾸면 `spec_version`·`game_version` 올리기.

## 2. 스킬 구성 — 직업당 6~7개, 역할마다 고를 거리

역할을 조금 늘린다: `Basic, Dps, Burst, Defense, GapClose` + **`Mobility`(회피·이동기)**, **`Setup`(버프·자원 준비)**. 각 직업 예시(수치는 출발점):

| 직업 | Dps (2개: 짧은 쿨 + 중간 쿨) | Burst | Setup | Defense | Mobility / GapClose |
|---|---|---|---|---|---|
| 전사 | 강타(6s, 분노 30), **회전베기**(10s, 근접 범위·분노 20) | 칼날폭풍(30s, 분노 50, 시전 2s) | **전투의 함성**(25s: 8초간 피해 +25%, 분노 +30) | 방패 막기(15s, 피해 60% 감소 4s) | 돌진(12s, gap close), **구르기**(8s, 3m 이동·0.4s 무적) |
| 마법사 | 화염구(마나 110, 시전 1.5s), **얼음창**(5s, 즉시·마나 60) | 메테오(40s, 마나 300, 시전 2.5s) | **마나 집중**(30s: 6초간 마나 재생 ×3, 그동안 피해 −20%) | 보호막(20s) | 순간이동(15s, 8m) |
| 궁수 | 조준 사격(4s, 집중 25, 시전 1s), **연사**(7s, 3연발·집중 20) | 속사(35s, 집중 40, 시전 2s) | **표식**(20s: 대상 10초간 받는 피해 +20%) | **덫**(18s: 보스 2초 속박) | 회피(12s, 6m 후퇴·1.5s 회피) |

- 기준: **평타 비중 ≤ 40%**, 모든 스킬이 판마다(늑대왕, 손 튜닝 default) **최소 1번** 쓰임. 측정값을 보고서에.
- `Mobility` 는 보스 패턴(경고 원·장판·돌진 띠)을 실제로 피하는 수단 — 쿨이 돌았으면 걸어서 피하는 대신 구르기/순간이동.
- `Setup` → `Burst` 콤보(함성 직후 칼날폭풍, 표식 후 속사)가 성립하면 이득이 크게.

## 3. BT 구조 — 블록 5개 + 블록 안 하위 트리

### 3.1 전략 블록 (유틸리티 선택, 학습 대상 가중치)

| 블록 | 가중치 | 필요도 N (예) | 하는 일 |
|---|---|---|---|
| burst | `w_burst` | 버스트 준비 + Setup 버프 중이면 ↑, 보스 취약 창(돌진 후 경직 등)이면 ↑ | Setup(준비 안 됐으면) → Burst 콤보 |
| dps | `w_dps` | 기본 (지금과 같음) | Dps 스킬 순환(쿨·자원·DPS 효율 순) → 평타 |
| survival | `w_survival` | 체력 θ 아래 ↑ (지금과 같음) | 물약 / Defense / 거리 두기 |
| **evade** (새) | `w_evade` | **`danger`** (보스 패턴 요청에서 생존 N 에 넣은 항을 여기로 옮긴다) | Mobility 쿨이면 사용, 아니면 안전 지점으로 걸어서 (보스 패턴 요청 3장 규칙) |
| **setup** (새) | `w_setup` | Setup 스킬 준비 + 버스트까지 남은 쿨 짧음 + 자원 부족 | Setup 스킬, 자원 쌓기(전사 분노는 평타로) |

- 원거리 직업의 거리 유지(`kite_distance`)는 dps 블록 안 조건으로 유지.
- 블록 전환 안정화(지금 생존 블록의 `SurvivalMaxHold`·`SurvivalLockout`)를 evade 에도: 같은 위험에 계속 들락날락하지 않게.
- `danger = 0`, 새 블록 가중치 0 이면 지금 BT 와 같은 선택이 나와야 한다 (회귀 확인용) — 가능하면 그런 시나리오/설정으로 0.7.1 결과와 비교.

### 3.2 블록 안 (고정 규칙, 학습하지 않음)

- **스킬 고르기**: 같은 역할 스킬 여러 개 → 사용 가능(쿨·자원·사거리·시전 중 위험 없음) 중 **점수 최대** — 점수 = (피해 또는 효과) / (시전 + 대기 시간), 동점은 데이터 순서 (결정적).
- **콤보(Sequence)**: Setup → Burst 를 한 블록 안 시퀀스로. 버프가 꺼지기 전에 Burst 가 불가능하면 Burst 를 아낀다.
- **시전 취소**: 시전 중 `danger` 가 생기면 evade 가 이길 때 시전을 끊고 피한다 (`cast_cancel` 로그).
- **자원 예약**: 기존 `resource_reserve` 를 Burst·Setup 비용 기준으로.
- 새 BT 상수(예: `evade_danger_threshold`, `combo_window`)는 `group: bt` + default, 모든 직업 같은 이름.

### 3.3 왜 이렇게 (학습 쪽 이유)

블록이 5개면 가중치 5개(실효 4) — **시작 상황(물약 수·체력·조합)마다 최적 비율이 달라지는** 공간이 된다. 물약이 적으면 evade·survival, 물약이 많으면 burst·setup 쪽이 유리한 식. 판 시작 한 번 고르는 IMPALA 밴딧(`../docs/BANDIT_IMPALA_DESIGN.md`)이 조합별 CMA-ES 보다 이점을 가질 수 있는 구조다.

## 4. 화면 — 스킬 바 (표시 전용)

- **위치**: 전투 화면 아래 가운데, 슬롯 6~7개 (단축키 번호 1~7 라벨, 스킬 이름 짧게 또는 아이콘 대용 색 블록).
- **쿨타임**: 슬롯 위로 **원형(시계 방향) 쓸기** + 남은 초 숫자(소수점 1자리 이하 정수). 쿨이 끝나면 짧게 반짝.
- **상태**: 자원 부족 = 회색 + 비용 숫자 빨강, 사거리 밖 = 테두리 빨강, 시전 중 = 슬롯 테두리 진행(기존 시전 바와 같은 진행률), **BT 가 지금 쓴 스킬** = 슬롯이 눌리는 연출 + 어느 블록이 골랐는지 작은 태그(burst/dps/…).
- 물약 슬롯도 같은 바에 (남은 수 = 가져간 수 − 사용, 물약 쿨다운 쓸기).
- **누를 수 없다**: 전투는 학습된 BT 가 한다. 버튼은 표시만 (`interactable = false`, 레이캐스트 막지 않음, 플레이 관찰 `screen.ui` 에도 넣지 않음 — 전투 중엔 LLM 이 행동하지 않는다).
- 넣을 곳: 밸런스 뷰어(`run/run_watch.py` 3창 비교·`--view`)와 플레이 모드 필드 전투 장면 둘 다. 3창 비교에서 **손 튜닝 vs 학습 결과의 스킬 사용 차이가 눈에 보이면** 성공.
- IMGUI(OnGUI) 든 uGUI 든 상관없음 (전투 화면은 관찰 대상이 아님). 다만 "QA 플레이어" 메모 패널·대화창과 겹치지 않게 (H1 참고).

## 5. 기록

- 전투 로그(뷰어용, 프로토콜 밖): `skill{name, block, role}` 에 `cooldown_ready_at` 추가, `combo{setup, burst}`, `cast_cancel{skill, reason}`, `dodge{skill|walk}`.
- 밸런스 `result` 는 그대로 (v1.3). 스킬별 통계가 프로토콜에 필요해지면 `PROTOCOL_CHANGE_REQUEST.md` 로.

## 6. 검증 · 보고 (`SKILL_BT_REPORT.md` 또는 보스 패턴 보고서에 장 추가)

1. `check-game` 전 항목 PASS (블록 5개 선언 확인: `python -m btqa_game check`), edge, 결정성, 판당 ms
2. 직업별 스킬 사용 분포 표 (늑대왕, 손 튜닝, n=100): 평타 ≤ 40%, 모든 스킬 ≥ 1회/판, 블록 비중
3. 손 튜닝 클리어율(직업 3 × stable, n=300) — 보스 패턴 요청의 40~70% 기준 유지
4. 회귀: `danger=0`·새 가중치 0 설정에서 0.7.1 과 선택 동일(가능한 범위)
5. 스크린샷: 스킬 바(쿨 도는 중 / 자원 부족 / BT 가 방금 쓴 스킬) + 3창 비교 1장
6. `play_check.py` / `python -m play_agent check-play` PASS
7. 학습 쪽에 알릴 것: 블록 이름·가중치 이름·range, 새 BT 상수, 바뀐 `spec_version`

학습 쪽은 받은 뒤 `run/run_measure_build.py` 로 재측정(기준선·CMA-ES·IMPALA), 그다음 밴딧 설계의 v1.4(`initial_state`) 작업으로 넘어간다.
